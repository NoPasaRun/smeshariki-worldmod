# WorldMod

**Роль (решение пользователя 2026-11-10): мод управления ландшафтом и отображением.** Типы мира, шейдерпак Iris, свет неба. Скрипты `tools/*.py` — **временные средства правки сохранённого мира** «Ромашковая Долина» (расщелина, пещера, лава, стрелы, ветер, снег, руины…): они лежат, чтобы при необходимости воссоздать то, что было сделано; их не развивают и не считают частью мода. Карта проекта — `../CLAUDE.md`.

Типы мира для Minecraft 26.2, Java 25, Fabric (Loom): «Остров Смешариков» (`buildmod:island`) и «Мир-океан» (`buildmod:ocean`). Выделен из BuildMod 2026-10-25. Пространство имён данных и идентификаторы остались `buildmod`, чтобы не ломать уже созданные миры (BuildMod ничего из этого больше не содержит — старый jar с островом вместе с новым не запускать: дубли регистрации).

## Правила работы

- **После каждой правки:** собрать (`./gradlew jar`) и положить `build/libs/worldmod-1.0.0.jar` в `~/.minecraft/mods/worldmod-1.0.0.jar`. Копировать только атомарно: `cp` во временный `.jar.tmp` в той же папке и `mv -f` (прямой `cp` поверх jar запущенной игры ломает её). Разрешено пользователем (как для BuildMod). Если сборка не прошла — ничего не копировать и сказать.
- Код: `src/main/java/com/smeshariki/world/` (`SmesharikiWorld` — регистрация, `IslandChunkGenerator`, `IslandBiomeSource`, `IslandMaps`). Карты острова: `src/main/resources/island/*.png`, строятся `tools/island_maps.py` (пути внутри скрипта абсолютные; предпросмотр `island_prev.png`, файлы `~/Изображения/*_сверху.png`). Мир-океан — только JSON в `data/buildmod/worldgen`.

Gradle `shaderPackZip` собирает `Smeshariki_Shaders.zip` и кладёт в jar (`/shaderpack/`), `ShaderPackInstaller` при запуске клиента копирует его в `~/.minecraft/shaderpacks/` (атомарно, только если содержимое отличается). Выбрать пак в игре: Настройки видео → Шейдеры. Первый запуск после установки Iris: пак мог появиться уже после того, как Iris прочитал папку, тогда перезапустить игру.
- Проходы: `shadow` (карта теней с сжатием к игроку), `composite` (тени, SSAO, дымка вдали), `final` (тёплый тон, насыщенность, контраст, виньетка). Настройки в `lib/settings.glsl`; по умолчанию тени и SSAO выключены (машина пользователя: Vega iGPU, 7 ГБ, 4 FPS на potato).
- Проверка компиляции без игры: все программы собираются и линкуются в OSMesa (Mesa, GL 4.5 compat) при всех сочетаниях `SHADOWS`/`SSAO`. В игре не проверено: смещения теней (прыщи/отрыв), нормали из `dFdx/dFdy` на краях силуэтов, цена выключенного прохода теней.
- В игре (2026-11-07, со слов пользователя): без `gbuffers_terrain`/`gbuffers_water` с Iris 1.11.4 + Sodium пропадала вся местность (оставались небо, сущности, свои блоки), после добавления этих двух программ (шаблон: текстура × цвет вершины × лайтмап) всё рисуется. Прорисовка 12, симуляция 10, тени и затемнение включены: около 40 FPS на Vega iGPU. Вид теней (прыщи, отрыв) не оценён.
- SSAO без ряби (2026-11-07): в `composite` AO пишется в `colortex1` с упорядоченным поворотом 4×4 (Байер) вместо шума по пикселю, в `composite1` блок 4×4 с весом по глубине усредняет шаблон и умножает цвет. Раньше 8 проб с шумом на пиксель давали «бегающее» зерно.
- Вода (2026-11-07): `block.properties` помечает воду id 10001, `gbuffers_water` пишет её маску в `colortex2` (r=1), `composite` для пикселей воды (depthtex0 < depthtex1) даёт цвет по глубине, небо по френелю (`fogColor`/`skyColor` по углу отражённого луча), блик солнца и процедурную рябь нормали (`waveH`, без текстур); опционально `WATER_SSR` (6–16 шагов по `depthtex1`, выкл. по умолчанию). Опции `WATER_FX` (вкл.), `WATER_REFLECT`, `WATER_WAVES`, `WATER_SSR`, `WATER_SSR_STEPS`. Компилируется в Mesa; в игре не проверено: срабатывание `mc_Entity` на воде в Iris 1.11.4/26.2 (если вода без эффекта — проверить id), вид волн и цена SSR.
- Свет и вид (2026-11-07): `lib/light.glsl` `lightTint` красит ванильный лайтмап в `gbuffers_terrain/water` (тёплый свет блоков, небо золотое на закате и синее ночью; ванильный лайтмап сохранён, чтобы работали гамма, ночное зрение, измерения); ветер в вершинном шейдере по `block.properties` (10003 листва — весь блок, 10004 трава/цветы — верх по `mc_midTexCoord`; в теневом проходе ветра нет); контур по глубине и цвет по времени суток, мягкое плечо яркости, виньетка — в `final`. Свечение: `colortex2.g` (id 10002 из блоков) + солнце → `composite2` → размытие `composite3/4` (`colortex3/4`, RGBA16F) → `final`. Лучи света: `composite5` (16 проб к солнцу по `depthtex0`). `program.compositeN.enabled=` пропускает проходы выключенных SSAO/BLOOM/GODRAYS (в Iris не проверено; проходы и без этого при выключенной опции ничего не делают). По умолчанию вкл.: цветной свет, время суток, тон-маппинг, контур 0,25, ветер, вода; выкл.: свечение, лучи, тени, SSAO, отражения воды. Компилируется в Mesa (80 вариантов), в игре не проверено.
- Грабли (2026-11-07): `const int colortexNFormat = RGBA16F;` в `lib/settings.glsl` (include) валит загрузку пака в Iris («`RGBA16F` undeclared»): Iris вырезает такие строки только из самого файла прохода. Перенос в файл прохода тоже не помог (Iris их не вырезает): правильно писать их внутри блочного комментария `/* const int colortex3Format = RGBA16F; */` в `final.fsh` и `composite2.fsh`: GLSL их не видит, Iris читает. Отрицательный контроль (константа без комментария) валит проверку в OSMesa-стенде.
- SSAO и наклон (2026-11-08, по жалобе «землю темнеет под углом»): прежний тест `zc - zсоседа > 0.04` считал любую поверхность, наклонённую к взгляду, заслонённой (соседи ниже по экрану всегда ближе к камере). Теперь соседняя точка заслоняет, только если лежит над плоскостью поверхности (`dot(v, normal)/|v| > 0.12`), нормаль из `dFdx/dFdy` считается в начале `main` вне ветвлений (`gn`). В игре не проверено.
- PBR из текстурпака (2026-11-08): ToonCraft (`~/.minecraft/resourcepacks/§aToonCraft.zip`, 128x) несёт `_n`/`_s` для 427 текстур. Формат по значениям каналов: `_s` r = гладкость (камень ~78, железо ~189, алмаз ~245), g = 0 почти везде (отражательной способности и металла нет), b = 0, a = 255 (свечения нет); `_n` rg = наклон (b = z или AO, z пересчитывается). `gbuffers_terrain` читает `normals`/`specular` (Iris) и `at_tangent`: рельеф как поправка к освещению солнцем (`ndlM - ndlG`), GGX-блик с Шлик-френелем (F0 ≥ 0,04) пишется в `colortex5` (вдвое), `composite` добавляет его с `litSun` из карты теней и не добавляет на воде. Свечение из `_s.a`, если < 255. Опции `PBR`, `PBR_BUMP`, `SPECULAR_STRENGTH`, `PBR_FLIP_Y` (направление Y у карт нормалей не проверено). Компилируется в Mesa (90 вариантов), в игре не проверено.
- Небо, туман, облака (2026-11-08): терраин-программа пака не применяет ванильный туман, поэтому край прорисовки был резким, а за ним небо ниже горизонта тёмное («полоса не синего неба»). В `composite`: туман к `fogColor` на `FOG_DISTANCE` (по умолчанию 170 блоков при прорисовке 12 = 192; ванильные `fogStart/End` не использованы: в 26.2 они мне неизвестны) и пикселям неба ниже горизонта (`dir.y` < 0,1) подмешан `fogColor` (солнце сохраняется по яркости). Облака свои: `addClouds` в `composite` по пикселям неба (плоскость на `CLOUD_HEIGHT`, fbm на value-noise, самозатенение по направлению к солнцу, золотые на закате, тёмные ночью), `clouds=off` в `shaders.properties` под `#ifdef CLOUDS` (поддержка `#ifdef` в properties не проверена). Тени облаков не делались. PBR: нормаль и касательная теперь из `dFdx/dFdy` (`viewPosV`, `texcoord`), без `gl_NormalMatrix`/`at_tangent`: подозрение на жалобу «всё темнеет, если смотреть выше горизонта» (причина не установлена, `PBR` выключается переключателем). Компилируется в Mesa (90 вариантов), в игре не проверено.
- Небо, облака, нормали (2026-11-08, по снимку и просьбам «туман не нужен», «облака объёмные, квадратные с закруглёнными краями», «тени и затемнение ложно появлялись на верхних гранях при взгляде выше горизонта»): туман убран. Небо целиком считает `composite` (`lib/sky.glsl`: градиент зенит—горизонт, золотой закат, ночь, свечение вокруг солнца; ниже горизонта цвет горизонта, ванильное небо оставлено только там, где яркость выше порога: солнце, луна, звёзды). Дальняя земля подмешивается к цвету горизонта неба (`HAZE`), не к `fogColor` (он серый). Облака — слой кубиков 16 блоков с радиусом закругления 2,4, трассировка по ячейкам (DDA), соседние кубики перекрываются на радиус (нет канавок), свет по нормали SDF, золотые/ночные тона, дальше ~470 блоков исчезают. Нормаль грани для теней и AO пишет `gbuffers_terrain` в `colortex6` (из `dFdx(viewPosV)`, точная), `composite` берёт её оттуда, а не восстанавливает из буфера глубины (там на дальних верхних гранях под скользящим углом она шумела и давала тени и AO), запасной вариант — старая из глубины (сущности, рука). Проверка без игры: `render_sky.py` (в сессии) рисует `composite.fsh` на искусственном небе в OSMesa (полдень, закат, ночь) — небо и облака проверены глазами, земля и тени нет. Не проверено в игре: `colortex6`, облака на реальных снимках, `clouds=off`.
- Золотой час (2026-11-08, по снимкам пользователя): облака, горизонт и склоны были кремовыми днём, потому что вес «золотого часа» шёл от `smoothstep(0.05, 0.55, sunH)` (до солнца 33° над горизонтом). Теперь `smoothstep(0.03, 0.30, sunH)` (до ~17°) в `lib/light.glsl`, `lib/sky.glsl`, `final.fsh`. Белые закорючки на снимках в небе и в джунглях, скорее всего, частицы маркеров ветра шара (карта), не шейдер.
- Верхние грани темнеют выше горизонта (2026-11-08, найдено по снимкам пользователя): `composite` разворачивал нормаль к камере проверкой `n.z < 0`. В пространстве камеры z нормали верхней грани = -n·forward: при взгляде выше горизонта он отрицательный, нормаль переворачивалась вниз, ndl < 0 давал тень, а AO считало соседей «над плоскостью» наоборот. Это же сидело в первой версии (через `dFdx/dFdy`). Теперь разворот по лучу: `dot(n, viewPos) > 0 → -n`. Проверено расчётом на 5 наклонах камеры (старый тест ломается ровно при 0°), в игре пока нет.
- **Дождь (2026-11-12, по просьбе «скай-бокс, освещение и тучи для дождливой погоды»; собрано, в игре не проверено).** Всё от одного коэффициента `RAIN_W` (`lib/settings.glsl`: uniform `rainStrength` Iris, сглажен `smoothstep`, множитель `RAIN_GLOOM`; `WET_W` — от `wetness`), переключатель `RAIN_FX` (вкл.). Небо (`lib/sky.glsl`): плоский серо-синий свод, зенит темнее горизонта, без свечения солнца и тёплого заката, ночью чуть светлее. Облака (`composite`): слой смыкается в сплошную пелену (`th` по покрытию 1,4), кубики выше на 0–5, серые с тёмным низом, без золотого тона; солнце, луна и звёзды из ванильного неба скрыты (`keep`). Свет (`lib/light.glsl`): небесный свет в дождь холодный серый и на ~14 % тусклее, только там, где `lm.y` высок (под крышей и от факелов не трогается); земля и листва на открытых местах темнеют до 22 % (`gbuffers_terrain`), блики солнца гаснут. Дымка вдали: ближе (с 16 блоков) и гуще, вода — рябь ×2,5 и без солнечного блика, `final` обесцвечивает (насыщенность 0,78) и холодит тон, лучи света выключены. Миксин `LightmapRenderStateExtractorMixin`: множитель света неба `SUN_BOOST` 6,25 в дождь плавно падает до `RAIN_BOOST` 1,5 по `ClientLevel.getRainLevel` (иначе усиление упирало ванильное снижение света неба в максимум, и без шейдеров дождь мир не темнил; в `key` проверки изменений добавлен уровень дождя). Проверка без игры: стенд на OSMesa (в сессии, `rt/r.c` + `drive.py`) — 45 вариантов компиляции (включая без `RAIN_FX`) без ошибок, небо и облака при дожде 0/0,5/1 в полдень, на закате и ночью смотрел по картинке. Не проверено в игре: что Iris отдаёт `rainStrength`/`wetness` в 26.2, вид земли и воды в дожде, сами капли (своей программы `gbuffers_weather` нет — рисуются ванильно, дымка на них действует), гроза (`thunderStrength` не используется), мягкость перехода. Дождь включает `/weather rain`.
